## Что нужно добавить (по приоритету)

### Критично — базовая функциональность блокнота
1. **Open** — открытие файла через `FileChooser`, чтение содержимого в `CodeArea` новой вкладки.
2. **Save / Save As** — запись содержимого текущей вкладки в файл; для уже открытого файла — сохранение по тому же пути без диалога.
3. **Exit** — реальное завершение приложения (`Platform.exit()`), с проверкой несохранённых изменений (см. ниже).
4. **Cut / Paste** — реализовать через встроенные `CodeArea.cut()` / `CodeArea.paste()`.
5. Исправить опечатку в `MainForm.fxml`: пункт меню `newMenuItem` имеет `text="Open"` вместо `"New"`.

### Важно — качество и удобство работы
6. Индикатор несохранённых изменений (например, `*` в заголовке вкладки при изменении текста — у `CodeArea` для этого есть `plainTextChanges()`/`multiPlainChanges()`).
7. Подтверждение закрытия вкладки/приложения при наличии несохранённых изменений.
8. Уникальные имена новых вкладок (`New File 1`, `New File 2`, …).
9. Диалог "Find" (иконка `Find.png` уже есть в ресурсах, но не подключена ни в FXML, ни в контроллере).
10. Undo/Redo — иконка `Undo.png` есть в ресурсах, но не подключена; `CodeArea` уже поддерживает `undo()`/`redo()` "из коробки".
11. Печать документа — иконка `Print.png` есть в ресурсах, функционал не подключён.
12. Строка состояния: номер строки/столбца, количество символов.

### Желательно — расширение функционала
13. Проверка орфографии (иконка `Spelling.png` уже в ресурсах) — потребует внешней библиотеки.
14. Список недавно открытых файлов (Recent Files).
15. Настройки/Preferences (шрифт, размер, тема — светлая/тёмная).
16. Drag-and-drop открытие файлов перетаскиванием в окно.
17. Определить назначение иконок `JST.png`, `LFT.png`, `RT.png` (предположительно выравнивание текста: по ширине/влево/вправо) и либо подключить, либо удалить как неиспользуемые.

### Технический долг
18. ~~Rich-text (Bold/Italic/Underline) архитектурно не реализуем на `TextArea`.~~ **Решено частично** — `TextArea` заменён на `CodeArea` (RichTextFX), что дало подсветку синтаксиса Java. Но Bold/Italic/Underline по-прежнему не реализуемы: `CodeArea` — это стилизуемый *plain-text* редактор (стили применяются программно через regex, не через выбор пользователем произвольного диапазона текста), а не WYSIWYG rich-text компонент. Для реальных Bold/Italic/Underline по-прежнему нужен либо `HTMLEditor`, либо кастомный rich-text редактор — отдельная задача.
19. Удалить неиспользуемые `@FXML`-поля меню (`newMenuItem`, `openMenuItem` и т.д.) в `MainFormController`, либо начать использовать их для управления состоянием (`disable`/`enable` в зависимости от контекста).
20. Заменить `System.out.println`-логирование на нормальный логгер (`java.util.logging` или `slf4j`), если проект будет расти.
21. Добавить unit-тесты хотя бы для `MainFormController` (после реализации Open/Save — тестировать чтение/запись файлов, работу с вкладками).
22. Убрать закоммиченный `NotepadM.iml` из git (`git rm --cached NotepadM.iml`) — файл уже в `.gitignore`, но был закоммичен раньше, чем добавили правило.
23. Подсветка синтаксиса сейчас жёстко привязана к Java (`JavaSyntaxHighlighter`) — при добавлении Open с определением языка по расширению файла потребуется абстракция "highlighter по языку" (сейчас сознательно не создавалась — не на чём было базировать выбор языка).
24. Подписка на изменения текста для подсветки (`codeArea.multiPlainChanges()...subscribe(...)`) не отписывается при закрытии вкладки — в проекте пока вообще нет логики закрытия/очистки вкладок. Учесть при реализации закрытия вкладок (пункт для будущей задачи), чтобы не копить "мёртвые" подписки.

## Известные ограничения окружения сборки
- Локальная сборка требует **JDK 21** и **Apache Maven** (в этой машине Maven установлен вручную в `%LOCALAPPDATA%\maven`, не через инсталлятор — не забудьте прописать `PATH`/`JAVA_HOME`, если открываете новый терминал).
- CI (`.github/workflows/main.yml`) использует `actions/setup-java@v4` с JDK 21 — держите версию синхронной с `pom.xml` (`maven.compiler.source/target`) и с `launch4j.jre.minVersion`.
